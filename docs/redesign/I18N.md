# I18N.md — Idiomas: inglés y español

Fase R3 del rediseño (`PLAN.md`), reglas en `REDESIGN.md` §8. El juego sale en **inglés** y en **español de
España**. El inglés es la fuente: sus claves y sus `{tokens}` son el contrato; el español se tipa contra él.

## Cómo funciona

Hay dos clases de texto y cada una tiene su sitio.

### 1. Textos de la interfaz → catálogos en `src/i18n/`

```
src/i18n/
  index.ts        lo que importa el resto del código
  core.ts         idioma actual, t(), tipos (sin React ni DOM: corre en Node)
  useT.ts         hooks de React
  names.ts        nombres de cosas de data/ en el idioma actual
  dataTexts.ts    la lista de textos visibles que declara data/
  en/<ns>.ts      catálogo inglés, un archivo por espacio de nombres
  es/<ns>.ts      el mismo espacio en español
```

```ts
import { t, useT, getLanguage, setLanguage, type Lang } from '@/i18n';

const t = useT();                        // en un componente: se repinta al cambiar el idioma
t('options.language');                   // "Language" / "Idioma"
t('options.exportFailed', { message });  // el tipo exige `message` porque el inglés lleva {message}
```

- Las claves son `'espacio.clave'` y están tipadas: una clave que no existe no compila.
- Los parámetros salen del texto inglés: un texto sin `{tokens}` no admite parámetros; uno con tokens los exige
  todos. Con una clave que solo se conoce en ejecución no se pueden comprobar, así que las familias de nombres
  elegidos en ejecución van en un `Record<Cosa, PlainTextKey>` (claves sin tokens; ejemplo en `names.ts`).
- `t()` también funciona fuera de React (un `window.confirm`, un aviso).

**Añadir un espacio de nombres** (por ejemplo `hud`) son dos archivos y dos líneas:

1. `src/i18n/en/hud.ts` → `export const hud = { gold: 'Gold' } as const;`
2. `src/i18n/es/hud.ts` → `import type { hud as en } from '../en/hud';`
   `export const hud: Record<keyof typeof en, string> = { gold: 'Oro' };`
3. Una línea en `en/index.ts` y la misma en `es/index.ts`: `export { hud } from './hud';`

Si al español le falta una clave, o el espacio entero, no compila.

**Las claves se usan literales** (`t('hud.gold')`, nunca `` t(`hud.${x}`) ``): una prueba falla por cada clave
que ningún archivo de `src/` menciona.

### 2. Textos de los datos → diccionarios en `src/data/i18n/es/`

`data/` sigue escribiendo en inglés y la simulación no sabe de idiomas (ESLint impide que `sim/` y `data/`
importen `i18n/`). Los textos visibles de los datos tienen su traducción en `src/data/i18n/es/<grupo>.json`:

```json
{ "attackDamage": { "en": "Attack Damage", "es": "Daño de ataque" } }
```

El `en` es el inglés **del que se tradujo**. La interfaz no lee `.name` ni `.label` de una tabla: pregunta a
`names.ts` (`statLabel`, `tierName`, `slotLabel`, `weaponTypeName`, `className`, `difficultyName`, `techName`,
`techDescription`, `techCategoryName`, `petName`, o el genérico `dataText(grupo, clave, inglés)`).

Grupos registrados (los estables): `stats`, `tiers`, `slots` (casillas y tipos de arma), `classes`,
`difficulties`, `tech` (categorías, nombres y descripciones), `pets`.

**Fuera por ahora:** habilidades, talentos y definitivas. Se están rediseñando (`CLASSES.md`) y tendrán su
grupo cuando ese contenido se cierre; traducir hoy los textos actuales sería trabajo perdido.

Los **cofres** no tienen nombre en `data/` (solo claves), así que sus nombres son textos de catálogo
(`chests.*`) y se piden con `chestName(tipo)`.

### El idioma

- Por defecto, el del sistema: español si `navigator.language` empieza por `es`; si no, inglés.
- Se elige en Ajustes. La elección se guarda con los demás ajustes de interfaz (`state/settingsShim`, clave
  `language`) y **solo desde que se elige**: hasta entonces el juego sigue al sistema.
- El idioma vive en `src/i18n/core.ts`, no en el store: `setLanguage` avisa a los componentes (`useT`) y a
  `uiSlice`, que lo persiste.

| Fallo | Prueba |

## Normas de traducción

- **Español de España, tuteando**: «Elige una de las dos», «Si caéis, retrocedéis una etapa» (al grupo, de
  vosotros).
- **Números y `{tokens}` exactamente como en inglés.** Cambia solo la forma: coma decimal y espacio antes de
  `%` y de las unidades («+2,5 %», «45 s», «15 min»).
- **Mayúsculas a la española**: solo la primera palabra y los nombres propios («Daño de ataque», «Jefe de
  mundo» solo a principio de frase). Nada de Mayúsculas En Cada Palabra.
- **Signos de apertura** siempre: «¿Partida nueva?», «¡Sintetizado!».
- **Comillas angulares** para las citas y el texto de ambientación: «Forjada para un juramento…».
- **Los nombres de clase no se traducen**: Knight, Ranger, Priest.
- **Las rarezas** se nombran en masculino cuando van solas («Épico»); como adjetivo concuerdan con la pieza
  («9 épicas», «1 gema épica», «espada legendaria»).
- **Breve.** La interfaz dice las cosas con signos; las palabras viven en los tooltips y van al grano.
- Cada idioma se nombra en sí mismo y no se traduce: English, Español.
